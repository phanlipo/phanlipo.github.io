      Anleitung & Hinweise

      Mit dem API-Check probierst du REST-APIs direkt im Browser aus. Aus einer OpenAPI- bzw. Swagger-Spezifikation entsteht für jeden Endpunkt ein Formular mit allen Parametern und einem Beispiel-Inhalt.

      Bedienung

      1. Unter Bearbeiten einen Namen, die API-URL und die Spezifikation angeben – als URL, Datei (.json, .yaml) oder eingefügten Text. Unterstützt werden OpenAPI 3.x und Swagger 2.0.
      2. Laden & speichern – die Konfiguration steht danach in der Auswahl oben und bleibt gespeichert. Mehrere APIs lassen sich nebeneinander anlegen.
      3. Bei Bedarf unter Anmeldung Bearer-Token, Benutzer/Passwort oder API-Schlüssel eintragen. Ist in der Spezifikation ein Verfahren beschrieben, ist es schon ausgewählt.
      4. Einen Endpunkt antippen, Felder ausfüllen (Pflichtfelder mit *) und Senden. Status, Dauer, Header und Inhalt der Antwort erscheinen darunter.
      5. Freie Anfrage geht immer – auch ohne Spezifikation: Methode, Pfad oder komplette URL und Inhalt selbst eintragen.

      Im Menü (☰) liegen der Verlauf der letzten Anfragen (antippen füllt das Formular wieder aus), „Daten sichern“ und diese Hilfe.

      Wenn keine Antwort kommt

      • CORS: Browser dürfen eine fremde API nur abfragen, wenn deren Server das erlaubt (Header Access-Control-Allow-Origin). Fehlt er, meldet der Browser nur „keine Antwort“. Das lässt sich in der App nicht umgehen – dann Als curl kopieren und im Terminal ausführen.
      • Nur https://-Adressen, außer http://localhost und http://127.0.0.1 für eigene Test-Server.
      • Nicht alle Antwort-Header sind für den Browser lesbar – nur die, die der Server freigibt.

      Datenschutz

      • Anfragen gehen direkt von deinem Browser an die API, die du einträgst – und nur dorthin. Es gibt keinen Zwischenserver.
      • Konfigurationen, Spezifikationen und Verlauf liegen nur in diesem Browser. Zugangsdaten werden nur gespeichert, wenn du den Haken setzt; dann stehen sie auch in der Sicherungsdatei.
      • YAML liest die Bibliothek js-yaml (MIT).

      KI-Agenten

      Ein KI-Agent im Browser (WebMCP) kann Konfigurationen und Endpunkte auflisten, eine Konfiguration wählen, das Formular ausfüllen und die letzte Antwort lesen. Senden musst du selbst – Agenten schicken keine Anfragen ab und sehen keine Zugangsdaten.

      API Check lets you try out REST APIs right in the browser. An OpenAPI or Swagger spec becomes a form for each endpoint, with all parameters and a sample body.

      How to use

      1. Under Edit, enter a name, the API URL and the spec – as a URL, a file (.json, .yaml) or pasted text. OpenAPI 3.x and Swagger 2.0 are supported.
      2. Load & save – the configuration then appears in the selection at the top and stays saved. You can keep several APIs side by side.
      3. If needed, enter a bearer token, user/password or API key under Sign-in. If the spec describes a method, it is preselected.
      4. Tap an endpoint, fill in the fields (required ones marked *) and Send. Status, duration, headers and body of the response appear below.
      5. Free request always works – even without a spec: enter method, path or full URL and body yourself.

      The menu (☰) holds the history of recent requests (tap one to fill the form again), “Back up data” and this help.

      If no response arrives

      • CORS: browsers may only call another site's API if its server allows it (header Access-Control-Allow-Origin). Without it the browser just reports “no response”. The app cannot get around this – use Copy as curl and run it in a terminal.
      • Only https:// addresses, except http://localhost and http://127.0.0.1 for your own test servers.
      • Not all response headers are readable in the browser – only those the server exposes.

      Privacy

      • Requests go straight from your browser to the API you enter – and nowhere else. There is no server in between.
      • Configurations, specs and history stay in this browser only. Credentials are only saved if you tick the box; then they are also in the backup file.
      • YAML is read by the js-yaml library (MIT).

      AI agents

      An AI agent in the browser (WebMCP) can list configurations and endpoints, select a configuration, fill in the form and read the last response. Sending is up to you – agents never send requests and never see credentials.

      Fehlersuche

      Klappt etwas nicht? Erst das Problem auslösen, dann die Diagnose kopieren und weitergeben. Sie enthält Browser, App-Version, Status und ein Protokoll der letzten Schritte – keine eingegebenen Inhalte.
