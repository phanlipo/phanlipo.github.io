        Anleitung & Hinweise

        Bild für Bild entscheiden: nach rechts wischen = gefällt mir, nach links wischen = weg. Die Bilder kommen aus Datenquellen, die du selbst als JSON einträgst – die App bringt keine fremden Inhalte mit.

        Bedienung

        • Wischen oder die Knöpfe unten: ✕ weg, ♥ gefällt mir, ↶ macht die letzte Bewertung rückgängig. Am Computer gehen auch die Pfeiltasten ← und →.
        • Profil und Datenquelle wählst du oben. Jedes Profil hat eigene Bewertungen; Profile legst du im Menü ☰ unter Profile an, benennst sie um oder löschst sie.
        • Ergebnis (♡ oben): Liste der gelikten bzw. weggewischten Einträge. Dort lässt sich jede Bewertung umdrehen oder entfernen, die Liste kopieren oder alles für diese Quelle zurücksetzen.
        • Datenquelle hinzufügen (Menü ☰ → Datenquellen): JSON einfügen oder als Datei öffnen, dann Hinzufügen. Zum Ausprobieren gibt es das Beispiel Emojis (feste Einträge, ganz ohne Internet).
        • Bei einer API-Quelle lädt die App erst nach einem Tipp auf Daten laden. Die Liste bleibt danach auf dem Gerät, angesehene Bilder auch – so geht es offline weiter. Neu laden holt die Liste erneut.

        Eindeutige id

        • Jede Quelle hat eine id (Buchstaben, Ziffern, . _ : -), jeder Eintrag ebenfalls (Feld per fields.id). Gespeichert wird je Profil: Quelle-id → Eintrags-id → like oder nope.
        • Fügst du eine Quelle mit derselben id erneut hinzu, wird sie ersetzt – die Bewertungen bleiben. Auch nach dem Löschen einer Quelle bleiben sie und kommen mit derselben id zurück.
        • Ändert sich die id, gilt es als neue Quelle. Einträge ohne id, ohne Bild/Text oder mit doppelter id werden übersprungen.

        Aufbau der JSON

        {
  "format": "image-swipe-source",
  "formatVersion": 1,
  "id": "meine-quelle",
  "title": "Titel" oder { "de": "…", "en": "…" },
  "attribution": "Quelle/Rechte (wird angezeigt)",
  "link": "https://…",
  "items": [ { "id": "1", "title": "…", "image": "https://…" } ]
}

        Statt items eine API: "api": { "url": "https://…", "list": "cards" } – url darf auch eine Liste von Adressen sein, list ist der Pfad zur Liste in der Antwort (leer = die Antwort ist selbst die Liste – oder ein einzelnes Objekt, dann ist es ein Eintrag). Mit fields sagst du, wo was steht: id, title, subtitle, image (Bild-Adresse) und text (z. B. ein Emoji statt Bild). Werte sind Pfade wie set.name oder Vorlagen mit geschweiften Klammern wie "{image}/high.webp"; {url|last} nimmt das letzte Stück einer Adresse (aus …/pokemon/132/ wird 132). Fehlt ein Feld in einer Vorlage, bleibt das Feld leer.

        Hinweise

        • Nutzungsrechte: Die App liefert keine Bilder oder Daten mit. Was du einträgst, rufst du selbst ab – achte auf die Bedingungen des jeweiligen Anbieters.
        • Wenn nichts lädt: Der Server muss Zugriffe aus Webseiten erlauben (CORS) – sonst blockiert der Browser die Antwort. Das gilt auch für die Bilder. Nur https (und http://localhost) geht.
        • Die App sendet keine Bewertungen oder anderen Daten an Server – nur einfache Abrufe ohne Cookies. Quellen, Profile und Bewertungen liegen in diesem Browser und sind in der Sicherung enthalten; geladene Listen und Bilder nicht (die lädt man neu).
        • KI-Agent: Ein KI-Agent im Browser kann die Quellen und das Ergebnis lesen (WebMCP), aber nichts bewerten oder laden. Jeder Aufruf erscheint hier als Hinweis.

        Decide picture by picture: swipe right = like, swipe left = pass. The pictures come from data sources you enter yourself as JSON – the app ships no third-party content.

        How to use

        • Swipe or use the buttons below: ✕ pass, ♥ like, ↶ undoes the last rating. On a computer the arrow keys ← and → work too.
        • Pick the profile and the data source at the top. Every profile has its own ratings; add, rename or delete profiles in the menu ☰ under Profiles.
        • Results (♡ at the top): list of liked or passed entries. There you can flip or remove each rating, copy the list or reset everything for this source.
        • Add a data source (menu ☰ → Data sources): paste JSON or open it as a file, then Add. To try it out there is the example Emojis (fixed entries, no internet at all).
        • For an API source the app only loads after you tap Load data. The list then stays on the device, and so do pictures you have seen – so you can carry on offline. Reload fetches the list again.

        Unique id

        • Every source has an id (letters, digits, . _ : -), and so does every entry (field set with fields.id). Stored per profile: source id → entry id → like or nope.
        • Adding a source with the same id again replaces it – the ratings stay. They also stay after deleting a source and come back with the same id.
        • A different id is a new source. Entries without id, without picture/text or with a duplicate id are skipped.

        JSON layout

        {
  "format": "image-swipe-source",
  "formatVersion": 1,
  "id": "my-source",
  "title": "Title" or { "de": "…", "en": "…" },
  "attribution": "source/rights (shown)",
  "link": "https://…",
  "items": [ { "id": "1", "title": "…", "image": "https://…" } ]
}

        Instead of items an API: "api": { "url": "https://…", "list": "cards" } – url may also be a list of addresses, list is the path to the list in the response (empty = the response itself is the list – or a single object, which is then one entry). fields says where things are: id, title, subtitle, image (picture address) and text (e.g. an emoji instead of a picture). Values are paths like set.name or templates with curly braces like "{image}/high.webp"; {url|last} takes the last part of an address (…/pokemon/132/ becomes 132). If a value in a template is missing, the field stays empty.

        Notes

        • Rights of use: the app ships no pictures or data. What you enter, you fetch yourself – mind the provider’s terms.
        • If nothing loads: the server has to allow requests from web pages (CORS) – otherwise the browser blocks the response. The same goes for the pictures. Only https (and http://localhost) works.
        • The app sends no ratings or other data to servers – only plain requests without cookies. Sources, profiles and ratings stay in this browser and are part of the backup; loaded lists and pictures are not (they are loaded again).
        • AI agent: an AI agent in the browser can read the sources and the results (WebMCP), but cannot rate or load anything. Every call shows up here as a notice.
